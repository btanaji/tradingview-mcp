NAME: MTF_Confluence
DESCRIPTION: Filter requiring HTF bias, mid-timeframe structure, and LTF entry trigger to all agree before allowing an entry
SYMBOL_DEFAULT: XAUUSD
TIMEFRAMES: 1d or 4h (HTF bias), 1h or 15m (mid timeframe), 5m or 1m (LTF entry)
FILTER_DEFINITION:
- HTF: determine trend direction using the same higher-high/higher-low or lower-low/lower-high test defined in OB_Continuation.
- Mid timeframe: confirm no counter-trend break of structure has occurred relative to the HTF direction.
- LTF: an entry signal generated by any other file in this rulebook is only actioned if both the HTF and mid-timeframe checks above agree with its direction.
- If the HTF or mid-timeframe checks disagree with the LTF signal's direction, discard the signal entirely; do not take the trade.
ENTRY_CONFIRMATION: [OPTIONS]
- close_beyond: once HTF and mid-timeframe checks in FILTER_DEFINITION both agree, the LTF candle closes beyond its own most recent minor swing point in the agreed direction — hardcoded generic trigger, since the parser cannot call another file's entry rule at runtime; this confirms structure has shifted on the LTF in the same direction the higher timeframes already support
- wick_reject: as an alternative, the LTF candle wicks into a minor swing point and closes back out in the agreed direction on the same candle — a faster hardcoded alternative to close_beyond
STOP_LOSS: [OPTIONS]
- swing_based: stop placed beyond the LTF swing point used to trigger entry — hardcoded generic rule, since the parser cannot reference another file's stop-loss logic
- fixed_atr: stop placed 1.5x ATR(14) beyond that same LTF swing point — use when it sits unusually close to entry
TAKE_PROFIT: [OPTIONS]
- fixed_2R: full close at a fixed 2R — hardcoded generic default
- partial_1_5R: partial close at 1.5R, remainder to breakeven and trailed by new mid-timeframe swing points — hardcoded generic default; the higher win rate that HTF/mid/LTF alignment tends to produce can support a larger trailed target
FILTERS:
- Reject any LTF signal that contradicts the HTF or mid-timeframe direction, with no exceptions
- Require the ratio between adjacent timeframes to be at least 4:1 (for example 1d->4h->15m, or 4h->1h->5m) when selecting which three timeframes to use
NOTES:
- This is a gating layer to run other strategy files through, not an independent signal generator. Implement as a shared filter module called by the other files rather than a standalone strategy.
- Parser compatibility: this file previously described its ENTRY_CONFIRMATION/STOP_LOSS/TAKE_PROFIT entirely as "inherit_from_underlying_strategy." The parser has no concept of cross-file inheritance, so a hardcoded, self-contained generic version is used above purely so this file parses on its own. If MTF_Confluence is wired into code as a literal boolean gate rather than a standalone strategy, the ENTRY_CONFIRMATION/STOP_LOSS/TAKE_PROFIT above can be disregarded in favor of whichever underlying file's own rules actually fire.
